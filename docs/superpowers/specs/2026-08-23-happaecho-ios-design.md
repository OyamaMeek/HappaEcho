# HappaEcho iOS 应用设计规格

**日期：** 2026-08-23  
**状态：** 已批准  
**产品名称：** HappaEcho

## 1. 目标与范围

HappaEcho 是一款原生 SwiftUI AI 对话应用，面向 iPhone 和 iPad。首版提供 OpenAI Chat Completions 兼容接口、流式文本与多模态图片输入、本地对话持久化、Markdown/代码/LaTeX 渲染，以及逐条消息同步到 Notion 的单向备份能力。

产品采用深色“高效工作台”视觉方向：保留克制的液态玻璃层次，但优先保证长回答、代码、表格和公式的可读性与信息密度。

### 1.1 平台约束

- 使用 Swift、SwiftUI、SwiftData、URLSession 和 Keychain。
- 最低部署目标为 iOS 17。原需求中的 iOS 16 与 SwiftData 不兼容，因此以 SwiftData 要求为准，不维护额外的 Core Data 兼容层。
- iPhone 使用堆叠导航；iPad 使用 `NavigationSplitView` 双栏布局。
- 应用保持单一应用 target，不引入额外业务模块或依赖注入框架。

### 1.2 首版不包含

- Notion 双向同步。
- 已发送消息编辑和远端 block 重写。
- OpenAI Chat Completions 兼容协议之外的供应商专属接口。
- CloudKit 多设备同步。
- 语音、通用文件附件和工具调用。
- token 预算管理、自动摘要和超长上下文裁剪。
- 长时间后台同步。应用启动或恢复活跃后继续未完成任务。
- 图片压缩或自动降质。

## 2. 架构

应用采用分层原生架构，各层通过明确接口协作。

### 2.1 Presentation

负责界面状态和用户交互，不直接构造外部 API 请求。

- `SidebarView`：新建、搜索和按时间分组的对话列表；展示生成和备份状态。
- `ChatView`：消息、流式草稿、输入区、附件预览、标题编辑和同步详情入口。
- `SettingsView`：聊天端点、API Key、模型、系统提示词、视觉能力和 Notion 设置。
- `ChatViewModel`、`SettingsViewModel`：将视图操作转交功能控制器。
- 通用组件：工作台表面、输入栏、消息内容、代码块、附件缩略图和备份状态。

### 2.2 Features

- `ChatSessionController`：发送、取消、流式聚合、上下文构建和消息持久化。
- `TitleGenerationCoordinator`：首轮模型标题生成、回退和手动标题保护。
- `NotionSyncCoordinator`：按对话串行执行同步任务，合并未开始的重复任务，维护重试和状态。
- `AttachmentStore`：导入原图、管理沙盒文件和清理孤立附件。

### 2.3 Services

- `ChatCompletionService` 协议及 OpenAI 兼容实现。
- `NotionService` 协议及 Notion API 实现。
- `KeychainService`。
- Markdown、LaTeX 和代码高亮渲染适配器。

具体渲染包在实现计划的依赖验证步骤中选择并锁定版本，因为当前仓库尚无 Xcode 工程可验证平台兼容性。候选包必须支持 iOS 17、Swift Package Manager、动态字体和允许商业分发的许可证；若任一能力不满足，则使用原生 `AttributedString`/自定义 SwiftUI 渲染器。无论选择何种实现，所有渲染能力都隐藏在 `MessageContentView` 后，业务层不依赖具体包。

### 2.4 Persistence

SwiftData 保存：

- `Conversation`
- `Message`
- `MessageAttachment`
- `NotionPageBinding`
- `AppSettings`

Keychain 只保存：

- 聊天 API Key
- Notion integration token

图片原始二进制保存到 Application Support 下按对话分组的附件目录。SwiftData 只记录元数据和相对路径。

## 3. 数据模型

### 3.1 Conversation

包含：

- UUID、标题、创建和更新时间。
- 消息关系和当前模型标识。
- `isTitleManuallyEdited`。
- Notion 页面绑定关系、最后同步时间和错误信息。每个绑定记录数据库 ID、page ID、创建时间和是否为当前绑定，从而保留更换数据库前的历史引用。
- 可由消息状态派生的 `none`、`syncing`、`success`、`failed` 状态。
- 当前是否正在生成。

删除对话时先取消对应生成与同步任务，再级联删除消息，并清理不再引用的附件文件。

### 3.2 Message

包含：

- 稳定 UUID、角色、正文、时间和顺序。
- `completed`、`stopped` 或 `failedPartial` 生成结果。
- 附件关系。
- `pending`、`syncing`、`synced` 或 `failed` Notion 同步状态。
- 同步时间、远端 block 标识、错误信息及增量同步游标。

已发送消息在首版中不可编辑。

### 3.3 MessageAttachment

包含：

- 稳定 UUID 和所属消息。
- 用户选择顺序。
- 原始文件名、UTType、MIME 类型、像素尺寸和文件大小。
- 沙盒相对路径。
- Notion 文件上传 ID、远端 URL、图片 block 标识和同步状态。

### 3.4 NotionPageBinding

每条绑定包含数据库 ID、page ID、创建时间和当前绑定标志。一条对话只能有一个当前绑定；更换数据库时将旧绑定转为历史记录，并创建新的当前绑定。

### 3.5 AppSettings

非敏感字段包括：

- Chat Completions 兼容端点。
- 模型标识、“支持图片输入”能力、可选单图字节上限和预计请求体上限。
- 可选系统提示词。
- Notion 是否启用、数据库 ID。

模型预设带默认视觉能力；自定义模型由用户明确设置能力，不根据名称猜测。

## 4. 聊天与流式数据流

### 4.1 发送文字消息

1. 验证输入和当前配置。
2. 创建并持久化用户消息。
3. 立即向 `NotionSyncCoordinator` 排入该消息的同步任务。
4. 创建仅存在于界面状态的助手草稿。
5. `ChatCompletionService` 通过 `URLSession.AsyncBytes` 逐行解析 SSE `data:` 事件。
6. 每个 `delta.content` 更新助手草稿；`[DONE]` 结束流。
7. 流结束后一次性持久化完整助手消息，并立即排入 Notion 同步。

同一对话同时只允许一个生成任务。切换对话不会取消生成，任务由会话控制器持有，侧边栏持续显示状态。

### 4.2 停止与失败

- 用户在收到首个非空增量后停止时，保存已有内容并标记为 `stopped`，随后同步该消息；首个非空增量前停止时不创建助手消息。
- 流在产生内容前失败时不创建空助手消息；显示可重试的内联错误。
- 流在产生部分内容后失败时保存内容，标记为 `failedPartial`，同步已有内容，并提供“继续生成”。
- Notion 失败不阻塞本地保存、模型回复或标题生成。

### 4.3 上下文

请求包含可选系统提示词，以及当前对话中截至新建用户消息为止的全部已持久化有效消息；每条消息按稳定顺序恰好编码一次。失败且为空的助手消息不进入上下文。

首版不自动估算或裁剪 token。服务端报告上下文超限时，已发送消息保持不可编辑；应用将失败用户消息的文字和附件复制回一个新的可编辑输入草稿，用户修改后重新发送。

## 5. 图片附件与多模态输入

### 5.1 来源与导入

支持：

- Photos Picker 多选照片库图片。
- 系统相机；处理设备无相机及权限拒绝。
- 文件选择器；限制为系统可解码图片，通过 security-scoped URL 复制到沙盒。

每次最多选择 10 张图片；达到上限后禁用继续添加并显示数量提示。输入区按选择顺序显示缩略图、文件大小和移除按钮。文件选择器直接复制所选文件字节；Photos Picker 使用 `.current` representation mode 获取当前资源表示，并在资源位于 iCloud 时显示下载进度；相机保存系统捕获返回的最高质量当前表示。这里的“原图”指上述来源交付给应用的未再次压缩、未转码字节，应用不承诺恢复照片资产在系统调整前的历史母版。

草稿取消时清理尚未发送的导入文件。图片解码失败、文件消失或读取失败时，指出具体附件并移除对应草稿项。

### 5.2 发送规则

发送前必须：

- 确认全部图片存在且可读取。
- 确认当前模型被配置为支持图片输入。
- 计算 Base64 后的预计请求体大小，并应用模型预设或用户为自定义端点配置的“单图上限”和“请求总上限”。未配置上限时仅执行本地可读性检查，由端点返回具体限制错误。

超过已配置限制时阻止发送并指出具体图片，不进行压缩。请求体采用文件支持的流式构造，避免同时在内存中保留所有图片的原始数据和 Base64 副本。

模型不支持视觉输入时阻止整条消息发送并提示更换模型；不静默丢弃图片，也不回退为纯文字请求。

OpenAI 兼容请求使用多模态 content 数组：文字写入 `text` 内容，原图以 Base64 Data URL 写入 `image_url` 内容。端点返回请求体或图片大小错误时保留完整草稿，指出失败文件并允许移除后重试。

## 6. 标题

- 新对话初始标题为“新对话”。
- 首轮助手消息以 `completed` 结束后，单独调用模型生成简短标题；`stopped` 和 `failedPartial` 不触发模型标题生成，先使用首条用户消息的截断文本，后续首个 `completed` 助手消息到达时再尝试一次。
- 每个对话最多启动一次模型标题请求。
- 清理引号、多余空白和换行，标题最多 30 个可见字符。
- 生成失败时回退为首条用户消息截断文本，不影响聊天。
- 用户可随时手动编辑标题。
- 手动编辑后设置 `isTitleManuallyEdited = true`，取消进行中的标题任务；即使取消存在竞态，结果落盘前也必须再次检查该标志，模型结果不得覆盖手动标题。
- 标题变化更新本地数据和 Notion 页面属性，不追加消息 block。

## 7. Notion 逐条增量同步

### 7.1 同步时机与页面模型

每条消息持久化后立即触发同步：用户消息不等待助手回复，助手消息在流结束、停止或部分失败内容落盘后同步。

每个对话对应一个 Notion 页面：

- 首条待同步消息创建页面并保存 `notionPageID`。
- 后续消息通过 append block children 增量追加。
- 标题、模型、更新时间和消息数通过独立元数据任务更新。

Notion 数据库需要以下属性：

- `Title`
- `Created`
- `Updated`
- `Model`
- `MessageCount`
- `Status`

### 7.2 顺序、合并和一致性

- 每条消息持久化时一律初始化为 `pending`；Notion 未启用时只暂停执行，不改变该状态。
- 同一对话内按消息创建顺序串行同步。
- 快速连续写入可合并进尚未开始的同一批次；进行中的请求不中断。
- 只有 `pending` 或 `failed` 消息进入任务。
- 本地数据是事实来源，Notion 是单向备份目标。
- 每条消息转换为确定顺序的 block 列表，并以 Notion 单次 block 数量限制拆分为批次。首个 block 写入纯文本标记 `happaecho-message:<messageUUID>:batch:<index>`；消息持久化 `nextBatchIndex`、每批远端 block ID 和最后确认时间。
- 每批追加成功后，在同一 SwiftData 事务中保存远端标识并推进游标。若响应丢失或应用中断，重试前分页读取当前页面的 block，查找精确 UUID/批次标记；找到则补记远端状态并继续下一批，未找到才重新追加。
- 消息只有在所有确定性批次均确认后才变为 `synced`，从而避免多请求追加时重复或遗漏。

### 7.3 文本与图片

页面正文中的每条消息包含角色、时间和正文。文本超过 Notion rich-text 限制时安全分段。代码尽量映射为 code block，其他 Markdown 映射为段落、标题、列表和引用；LaTeX 保留原始公式文本。

包含图片的消息仍作为一个逻辑同步单元，但可通过多个可恢复批次完成：

1. 上传所有原图。
2. 保存每个成功上传的文件标识。
3. 按用户选择顺序构造图片 block，并与文字 block 组成确定性 block 序列。
4. 按 Notion 单次追加上限拆分并逐批追加，每批沿用 UUID/批次标记和持久化游标。
5. 只有文字及全部图片 block 都确认写入后，消息才变为 `synced`。

部分图片上传失败时消息保持 `failed`；重试只处理未完成阶段。Notion 不支持格式或文件超限时显示明确错误，不生成降质副本。

### 7.4 重试与状态

- `401/403`：立即失败，提示检查 token、数据库权限和共享设置。
- `404`：提示数据库或页面不可访问，不自动创建重复页面。
- `429`、`5xx` 和网络中断：指数退避自动重试最多 3 次，并遵守 `Retry-After`。
- 重试耗尽后标记 `failed`，可从侧边栏、聊天顶部或同步详情手动重试。

对话级状态：

- 存在执行中任务：`syncing`。
- 存在失败消息：`failed`。
- 所有现有消息均同步：`success`。
- Notion 未启用或尚无同步记录：`none`。

禁用 Notion 后暂停队列执行，但所有新消息仍保持 `pending`，并保留 token、页面绑定和状态。重新启用后按创建顺序扫描并排入全部 `pending` 和 `failed` 消息。更换数据库 ID 后，将当前 `NotionPageBinding` 标记为历史绑定；现有对话首次向新数据库同步时创建新的当前绑定，旧引用继续用于诊断，不会向错误数据库追加。

## 8. 界面设计

### 8.1 iPad 高效工作台

- `NavigationSplitView` 双栏布局。
- 左栏约 280–320pt，包含新对话、搜索、按时间分组的历史记录、生成状态和同步状态。
- 右栏使用紧凑顶栏、最大化消息阅读区和固定底部输入区。
- 玻璃仅用于侧栏、顶栏、输入框和浮层；长回答使用接近实色的低干扰背景。
- 代码块、表格和块级公式可横向滚动。

### 8.2 iPhone

- 对话列表和聊天页使用堆叠导航。
- 标题可点击编辑。
- Notion 状态显示为紧凑图标，点击后打开底部详情页。
- 输入框支持多行，并随键盘上移。
- 流式输出仅在用户位于底部附近时自动跟随，避免打断向上阅读。

### 8.3 消息渲染

- 用户消息使用低饱和靛蓝实色气泡。
- 助手消息弱化边界，以 Markdown 文档结构为主。
- `MessageContentView` 统一处理标题、列表、引用、链接、表格、行内和块级代码、行内和块级 LaTeX。
- 代码块提供语言标签、复制按钮和横向滚动。
- 单个公式、Markdown 节点或代码块渲染失败时显示原始文本，不破坏整条消息。
- 支持 Dynamic Type、VoiceOver、Reduce Transparency 和 Reduce Motion。

### 8.4 设置页

分为：

1. 聊天接口：端点、API Key、模型、视觉能力和系统提示词。
2. Notion：启用开关、token、数据库 ID、连接测试和逐条同步说明。
3. 外观与关于：应用信息与依赖许可。

敏感字段默认隐藏，可临时显示。保存后不将 Keychain 明文写回 SwiftData。首版不显示没有实际地址的隐私政策入口。

## 9. 错误处理原则

- 错误必须定位到具体操作或附件，并提供恢复动作。
- 本地消息写入成功后，外部同步失败不得回滚消息。
- 配置或能力校验在发起网络请求前完成。
- 解析或渲染错误采用可读原文降级。
- 删除前取消关联异步任务，防止完成回调写入已删除模型。
- 外部服务错误统一映射为稳定的领域错误，视图不直接解释 HTTP 响应。

## 11. 完成标准

首版完成必须满足：

- 非敏感设置可持久化，两个 token 仅存在 Keychain。
- 流式聊天可发送、停止和失败恢复，并保存完整或部分回复。
- 支持从照片库、相机和文件导入最多 10 张原图。
- 原图不被压缩或转码；不支持视觉的模型会在发送前阻止请求。
- 首轮自动生成标题，且手动标题永不被模型覆盖。
- 每条持久化消息都会触发 Notion 增量同步。
- 文字与所有图片 block 成功后，消息才显示同步成功。
- 重试或重启不会重复追加已确认同步的消息和图片。
- 对话列表与详情准确显示 `none/syncing/success/failed`。
